# 路线图

计划中的版本和功能。已经发布的版本实际改了什么，见 [CHANGELOG.md](../CHANGELOG.md)。

维护方式：

- 新需求讨论定了，就写进对应版本，状态用 ⬜ 未开始、🔄 进行中、✅ 完成。
- 版本发布时，把这里的内容整理进 CHANGELOG，并打 git 标签（如 `v0.3.0`）。
- 讨论过、但还没决定做不做的，放在“待定”。

## 0.3.0：客户相册（第一期：本地发布）✅

已于 2026-11-17 发布。

- ✅ 同一个容器跑管理员端和客户端两个端口；客户端没有管理员接口，不接触照片目录
- ✅ 从筛选界面发布相册：用这次出门的已选照片生成快照（带水印的 2048px 预览）
- ✅ 发布选项：标题、客户名、留言、语言（跟随浏览器 / 中文 / English）、张数上限（超出不能提交 / 提醒后可提交）、水印、公开或密码、截止日期、自动删除日期
- ✅ 每个相册唯一编号和随机链接；可重置链接
- ✅ 客户页面：以手机为主，复用管理员端的浏览组件；选中、备注、只看已选、提交；显示截止和自动删除日期
- ✅ 导出客户所选 RAW 到 `<出门目录>/client_<发布日期>_<编号>/`（可改名），规则和 `select/` 一样
- ✅ 交付成片：从出门目录下的子文件夹（排除 jpg、raw、select）导入，客户单张下载或打包下载
- ✅ 到期自动删除相册文件，保留客户的选择和备注
- ✅ 设置：水印文字（默认“严记肘子铺”）、客户访问地址
- ✅ 版本管理：路线图、更新记录、git 标签

## 0.4.0：客户相册（第二期：对外访问与云端发布）⬜

- ⬜ 对外访问：域名 + Cloudflare Tunnel，隧道只接客户端端口；部署文档
- ⬜ 云服务器上的“仅客户端模式”：同一个镜像，不挂照片目录
- ⬜ 发布位置可选“本地”或“云端”：推送相册包（逐个文件、可续传），拉回客户的选择和备注
- ⬜ 成片交付走云端（不经过 Cloudflare 代理，避开免费套餐对大文件的限制）

## 待定

讨论过，还没决定：

- 预览缓存设上限（比如 50GB），按最近打开时间清理最久没用的出门目录；设置页显示占用并可手动清理
- 首页的已选数、张数存进表里，文件夹很多时首页也一样快
- 标签页回到前台时的自动刷新限流（最多每分钟一次）
- 大预览从 2560px 改成 2048px，缓存小约 40%
- 模板方式一条命令完成更新（构建后自动用新镜像重建容器）
- `deploy.sh` 和 `deploy.env.example` 的默认值只写一处

## 暂不做

- 星级、颜色标签，写 XMP 给 Lightroom
- 连拍分组、并排对比
- 删除或移动废片
- 管理员端的登录和外网访问
- 直接从 SD 卡导入
- 在线收费、客户提交时通知摄影师
